# Аутентификация клиентов

Фронтенд хранит access/refresh JWT в `localStorage` и Pinia. Клиентский плагин
восстанавливает профиль до выполнения middleware. `/profile`, `/profile/**`,
`/cart` и `/checkout` рендерятся на клиенте; публичные страницы сохраняют SSR.

## Серверная сессия и токены

Каждый успешный вход или подтверждение PIN создаёт `CustomerSession`. Её UUID
передаётся в claim `sid` обоих JWT. Проверяются подпись, срок действия, активность
и подтверждённый email пользователя, а также отсутствие отзыва сессии.
Старые JWT без `sid` отклоняются: после обновления потребуется повторный вход.

Refresh вращается через Simple JWT: клиент сохраняет **оба** новых токена,
а использованный refresh попадает в blacklist. Все URL выдачи и обновления JWT
используют одинаковые проверки. Смена пароля и изменение email отзывают все
серверные сессии пользователя. Обычный выход отзывает только текущую сессию,
немедленно делая непригодными её access и refresh.

`POST /api/auth/logout/` принимает refresh без access-заголовка. Подписанный
refresh, уже заменённый ротацией, также может отозвать свою сессию — это закрывает
гонку выхода и обновления. Он не может получить новые токены.
При сетевом сбое выход очищает браузерную сессию, но серверный отзыв не гарантирован.

## Email и пароль

- Регистрация: неактивный аккаунт, неподтверждённый email, PIN на 10 минут по умолчанию.
- Повторная отправка заменяет PIN. Повторное подтверждение уже подтверждённого email
  возвращает ошибку с предложением войти по паролю, а не ответ без токенов с кодом 200.
- Email сравнивается без учёта регистра. Непустые email защищены уникальным индексом.
  Пустые email старых служебных аккаунтов разрешены; публичная регистрация требует email.
- Изменение email в профиле деактивирует аккаунт, отзывает сессии и отправляет новый PIN.
  Фронтенд переходит к подтверждению. При ошибке отправки изменение откатывается.
- `POST`, `PUT` и `PATCH /api/auth/change-password/` требуют старый пароль и проверяют
  новый штатными валидаторами Django. После успеха нужно войти с новым паролем.

## Применение

Перед запуском обновлённого бэкенда создайте резервную копию базы и выполните
миграции с настройками нужного окружения:

```bash
venv/bin/python manage.py migrate
```

Для production с явными настройками:

```bash
venv/bin/python manage.py migrate --settings=core.settings.prod
```

Нужны миграции `authentication.0003_customer_sessions_and_email_identity` и приложения
`token_blacklist`. Если уже существуют непустые email, совпадающие без учёта регистра,
миграция остановится с понятной ошибкой. Она не объединяет и не удаляет аккаунты:
дубликаты нужно разрешить до повторного запуска. Старые неподтверждённые аккаунты
не помечаются подтверждёнными автоматически.

Для очистки истёкших записей Simple JWT запускайте штатную команду:

```bash
venv/bin/python manage.py flushexpiredtokens
```

## Проверки

Из каталога бэкенда (SQLite в памяти, письма в памяти, рабочая БД не используется):

```bash
venv/bin/python manage.py test apps.authentication.tests --settings=core.settings.test_auth
```

Из каталога фронтенда:

```bash
pnpm test:auth
pnpm typecheck
```

Фронтенд-тесты исполняют настоящий Pinia store, Axios interceptors и middleware
с подменой HTTP и окружения Nuxt. Они не заменяют проверку в браузере.
